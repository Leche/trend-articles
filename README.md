# 트렌드림 (Trend Dream)

매일 아침, 프로덕트·기술 아티클을 자동으로 큐레이션해 다이제스트로 만들어 발행하는 개인 운영 파이프라인입니다. GitHub Actions·GitHub Pages·Claude API·외부 cron·KakaoWork 봇을 조합해, **"평일 아침 초안 자동 생성 → 모바일에서 검수 → 정해진 시각 자동 발행"** 흐름을 무인에 가깝게 운영합니다.

- **결과물**: https://leche.github.io/trend-articles/
- **운영 대시보드**: `trigger.html` (모바일에서 검수·수정·발행을 조작하는 컨트롤 패널)

---

## 운영 컨셉

하루 사이클은 세 단계로 나뉩니다.

1. **생성 (자동, 무인)** — 평일 아침, 외부 cron이 큐레이션 워크플로우를 깨워 그날의 기사 8개를 선정·요약하고 다이제스트 HTML을 만들어 커밋합니다.
2. **검수 (수동, 모바일)** — 출근길 등에서 `trigger.html`을 열어 기사 교체·순서 조정·썸네일 교체·링크 수정·인트로 확인을 하고, 만족스러우면 발행을 예약합니다.
3. **발행 (자동, 예약)** — 예약된 시각에 다이제스트를 그룹 채널에 자동 게시하고, 각 단계 결과를 KakaoWork로 알립니다.

큐레이션 결과물은 **"발행 전 초안"** 이라는 점이 설계의 핵심입니다. 자동 생성이 실패하거나 품질이 아쉬우면 손으로 고치면 되고, 자동화의 진짜 목표는 "매일 아침 검수할 초안이 준비되어 있는 것"입니다.

## 아키텍처

```
                    ┌───────────────────┐
   외부 cron ─────▶ │  curate.yml       │  기사 선정·요약·썸네일·HTML 생성
 (평일 08:50 KST)   │  (Claude API)     │  → YYYY-MM-DD/index.html + index.html 커밋
                    └─────────┬─────────┘
                              │ push
                              ▼
                    ┌───────────────────┐
                    │ GitHub Pages 빌드  │  사이트 배포
                    └─────────┬─────────┘
                              │ 배포 완료
                              ▼
   trigger.html ───▶ 검수·교체·순서·썸네일·링크·AI명령 (workflow_dispatch)
   (모바일 대시보드)          │
                              │ 발행 예약 (pending-publish.json)
                              ▼
                    ┌───────────────────┐
   외부 cron ─────▶ │  agit-post.yml    │  예약 시각에 그룹 채널 자동 게시
 (09:30 KST)        └─────────┬─────────┘
                              ▼
                    ┌───────────────────┐
   모든 단계 ──────▶ │  notify.yml       │  KakaoWork 알림 (성공/실패)
                    └───────────────────┘
```

### 왜 외부 cron인가

GitHub Actions의 `schedule:` 트리거는 인덱싱이 비결정적이라 정시 실행 누락이 잦습니다. 그래서 native schedule을 제거하고, **외부 cron(cron-job.org)이 정해진 시각에 `workflow_dispatch`를 호출**하는 구조로 전환했습니다. 발화 신뢰도가 올라가고, 실행 주체(자동 cron / 모바일 수동)를 구분해 다루기도 쉬워졌습니다.

## 구성 요소

### 워크플로우 (`.github/workflows/`)

| 파일 | 이름 | 역할 |
|------|------|------|
| `curate.yml` | 트렌드림 기사 큐레이션 | 기사 선정 → 요약 → 썸네일 → HTML 생성. 평일 아침 자동 실행 및 모바일 수동 실행 |
| `agit-post.yml` | Agit 게시 | 예약 시각에 다이제스트를 그룹 채널에 게시. 게시 전 데이터 유효성 검증 |
| `notify.yml` | Notify Digest | Pages 배포 성공 시 결과 알림, 콘텐츠 워크플로우 실패 시 실패 알림 |
| `command.yml` | 트렌드림 AI 명령 실행 | 자연어 명령을 Claude가 해석해 HTML을 직접 수정 |
| `repurpose.yml` | 다이제스트 다음 영업일로 미루기 | 놀금·공휴일로 건너뛴 다이제스트를 다음 영업일로 재활용 |

### 스크립트 (`scripts/`)

- **`curate.py`** — 큐레이션 엔진. 우선 사이트 스캔 → Claude API로 기사 선정·요약 → 썸네일 다운로드 → 인트로 생성 → HTML 조립. 기사 교체(replace) 모드, 다음날 발행용 저녁 큐레이션 모드도 포함.
- **`command.py`** — 자연어 명령 해석기. "N번 기사 링크 교체", "제목 수정" 등을 Claude로 파싱해 HTML을 수정.
- **`inject_gnb.py`** — 생성된 HTML에 공통 내비게이션(GNB)·앵커 링크를 주입.
- **`patch_darkmode.py`** — 과거 다이제스트에 다크모드 CSS를 일괄 소급 적용하는 유지보수용 스크립트.

### 운영 대시보드 (`trigger.html`)

모바일에서 여는 단일 페이지 컨트롤 패널. 각 버튼이 GitHub API `workflow_dispatch`를 호출합니다.

- **새 큐레이션 생성** — 오늘 다이제스트를 새로 생성/재생성
- **기사 교체** — 특정 번호의 기사를 다른 URL로 교체
- **순서 조정 / 썸네일 교체 / 링크 수정** — 개별 요소 수정
- **AI 명령 실행** — 자연어로 HTML 편집
- **발행 예약 / 즉시 게시 / 다음 영업일로 미루기** — 발행 제어
- 이미 발행된 다이제스트를 덮어쓰지 않도록, 덮어쓰기 성격의 액션에는 발행 상태 기반 가드가 걸려 있습니다.

## 큐레이션 로직

- **소스**: 국내외 프로덕트·디자인·테크 블로그 및 뉴스룸의 화이트리스트를 스캔해 후보를 모읍니다. (`CURATE_MODE=web_search`로 전환하면 Claude의 웹 검색으로 인터넷 전체에서 큐레이션할 수도 있습니다.)
- **선정·요약**: Claude API가 후보 중 8개를 선정하고, 각 기사에 한 줄 요약 + 3줄 요약을 생성합니다.
- **인트로**: 선정된 8개를 종합해 "왜 지금 이 주제들이 중요한가(so-what)" 관점의 다이제스트 인트로를 생성합니다. 최근 인트로들과 톤이 겹치지 않도록 회피 로직이 있습니다.
- **본문 스크랩 폴백**: 일반 요청을 로그인 페이지로 리다이렉트하는 사이트(예: 브런치)를 대비해, 인증 리다이렉트를 감지하면 검색 크롤러 User-Agent로 재시도하고, 그래도 안 되면 렌더링 브라우저 → 캐시 순으로 폴백합니다.
- **중복 방지**: 같은 큐레이션 내 중복 및 과거 발행 기사와의 중복을 제거합니다.

## 발행 흐름

1. 검수를 마치면 `trigger.html`에서 발행을 예약 → `pending-publish.json`에 대상 날짜·시각이 기록됩니다.
2. 외부 cron이 아침에 게시 워크플로우를 호출 → `pending-publish.json`을 확인해 예약이 있으면 발행합니다.
3. 게시 직전 **데이터 유효성 검증**(기사 제목·인트로 추출 가능 여부)을 먼저 돌려, 문제가 있으면 게시하지 않고 즉시 알림을 보냅니다. 발행 시각 전에 여유를 두고 고칠 수 있습니다.
4. 발행 후 `pending-publish.json`을 비웁니다.

---

## 알림

모든 콘텐츠 변경은 Pages 재배포를 유발하고, 그 배포가 끝난 시점(=사이트가 실제로 새 내용을 서빙하는 시점)에 KakaoWork로 결과 알림이 발사됩니다. 커밋 메시지 첫 글자(이모지)로 어떤 액션이었는지 분류해 라벨과 다이제스트 링크를 함께 보냅니다. 콘텐츠 워크플로우가 실패해 배포까지 못 가는 경우에는 실패 자체를 별도로 알립니다.

## 기술 스택

- **자동화**: GitHub Actions (`workflow_dispatch` 중심) + 외부 cron(cron-job.org)
- **호스팅**: GitHub Pages
- **AI**: Claude API (기사 선정·요약·인트로·자연어 명령)
- **스크래핑**: requests / Playwright / 검색 크롤러 UA 폴백
- **알림**: KakaoWork Incoming Webhook (Block Kit)
- **런타임**: Python 3.11
