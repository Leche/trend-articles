# 트렌드림 (Trend Dream)

매일 아침, 프로덕트·기술 아티클을 자동으로 큐레이션해 다이제스트로 만들어 발행하는 개인 운영 파이프라인입니다. GitHub Actions·GitHub Pages·Claude API·외부 cron·KakaoWork 봇을 조합해, **"전날 밤 초안 자동 생성 → 모바일에서 검수 → 다음날 아침 자동 발행"** 흐름을 무인에 가깝게 운영합니다.

- **결과물**: https://leche.github.io/trend-articles/
- **운영 대시보드**: `trigger.html` (모바일에서 검수·수정·발행을 조작하는 컨트롤 패널)

---

## 운영 컨셉

하루 사이클은 세 단계로 나뉘고, **전날 밤 22시에 다음날 다이제스트를 미리 만들어 두는 구조**입니다.

1. **생성 (자동, 무인, 전날 22:00 KST)** — 외부 cron이 `for_tomorrow=true`로 큐레이션 워크플로우를 깨워, **내일 KST** 날짜 폴더로 기사 8개를 선정·요약해 다이제스트 HTML을 만들고 커밋합니다.
2. **검수 (수동, 모바일)** — 밤이나 다음날 출근길 등에서 `trigger.html`을 열어 기사 교체·순서 조정·썸네일 교체·링크 수정·인트로 확인을 하고, 만족스러우면 발행(다음날 09:30)을 예약합니다.
3. **발행 (자동, 예약, 09:30 KST)** — 외부 cron이 매일 아침 게시 워크플로우를 호출하고, `pending-publish.json`에 오늘 날짜 예약이 있으면 그룹 채널에 자동 게시합니다. 각 단계 결과는 KakaoWork로 알립니다.

**왜 22시 생성 + 09:30 발행으로 분리했는가**: 처음엔 22시에 큐레이션을 만들고 그 안에서 익일 09:30까지 대기(sleep)했다가 발행하는 단일 워크플로우로 설계했지만, GitHub Actions job은 최대 6시간 제한이 있어 11시간 넘는 sleep이 불가능했습니다. 그래서 생성(`curate.yml`)과 발행(`agit-post.yml`)을 완전히 분리된 두 워크플로우로 쪼개고, 그 사이 신호는 `pending-publish.json` 플래그 파일로 전달하는 구조로 바꿨습니다.

큐레이션 결과물은 **"발행 전 초안"** 이라는 점이 설계의 핵심입니다. 자동 생성이 실패하거나 품질이 아쉬우면 밤~아침 사이 손으로 고치면 되고, 자동화의 진짜 목표는 "발행 전 검수할 초안이 미리 준비되어 있는 것"입니다.

## 아키텍처

```
                    ┌───────────────────┐
   외부 cron ─────▶ │  curate.yml       │  기사 선정·요약·썸네일·HTML 생성 (내일 KST 폴더)
 (전날 22:00 KST)   │  (Claude API)     │  → YYYY-MM-DD/index.html + index.html 커밋
   for_tomorrow=true└─────────┬─────────┘
                              │ push
                              ▼
                    ┌───────────────────┐
                    │ GitHub Pages 빌드  │  사이트 배포
                    └─────────┬─────────┘
                              │ 배포 완료
                              ▼
   trigger.html ───▶ 검수·교체(workflow_dispatch) / 순서·썸네일·링크(contents API 직접 커밋)
   (모바일 대시보드)          │
                              │ 발행 예약 (pending-publish.json 직접 커밋)
                              ▼
                    ┌───────────────────┐
   외부 cron ─────▶ │  agit-post.yml    │  pending 확인 → 데이터 검증 → 그룹 채널 게시
 (09:30 KST)        └─────────┬─────────┘
                              ▼
                    ┌───────────────────┐
   모든 단계 ──────▶ │  notify.yml       │  KakaoWork 알림 (성공/실패)
                    └───────────────────┘

   trigger.html ───▶ repurpose.yml   놀금·공휴일로 건너뛴 다이제스트를
   (미루기 버튼)                       다음 영업일로 재배치 + 발행 예약
```

### 왜 외부 cron인가

GitHub Actions의 `schedule:` 트리거는 인덱싱이 비결정적이라 정시 실행 누락이 잦습니다. 그래서 native schedule을 제거하고, **외부 cron(cron-job.org)이 정해진 시각에 `workflow_dispatch`를 호출**하는 구조로 전환했습니다. 발화 신뢰도가 올라가고, 실행 주체(자동 cron / 모바일 수동)를 구분해 다루기도 쉬워졌습니다.

## 구성 요소

### 워크플로우 (`.github/workflows/`)

| 파일 | 이름 | 역할 |
|------|------|------|
| `curate.yml` | 트렌드림 기사 큐레이션 | 기사 선정 → 요약 → 썸네일 → HTML 생성. 전날 22시 자동 실행(`for_tomorrow=true`) 및 모바일 수동 실행 |
| `agit-post.yml` | Agit 게시 | 예약 시각에 다이제스트를 그룹 채널에 게시. 게시 전 데이터 유효성 검증 |
| `notify.yml` | Notify Digest | Pages 배포 성공 시 결과 알림, 콘텐츠 워크플로우 실패 시 실패 알림 |
| `command.yml` | 트렌드림 AI 명령 실행 | 자연어 명령을 Claude가 해석해 HTML을 직접 수정 |
| `repurpose.yml` | 다이제스트 다음 영업일로 미루기 | 놀금·공휴일로 건너뛴 다이제스트를 다음 영업일로 재활용 |

### 스크립트 (`scripts/`)

- **`curate.py`** — 큐레이션 엔진. 우선 사이트 스캔 → Claude API로 기사 선정·요약 → 썸네일 다운로드 → 인트로 생성 → HTML 조립. 기사 교체(replace) 모드, 다음날 폴더로 생성하는 `for_tomorrow` 모드도 포함.
- **`command.py`** — 자연어 명령 해석기. "N번 기사 링크 교체", "제목 수정" 등을 Claude로 파싱해 HTML을 수정.
- **`inject_gnb.py`** — 생성된 HTML에 공통 내비게이션(GNB)·앵커 링크를 주입.
- **`patch_darkmode.py`** — 과거 다이제스트에 다크모드 CSS를 일괄 소급 적용하는 유지보수용 스크립트.

### 데이터 파일 (저장소 루트)

- **`YYYY-MM-DD/index.html`** — 날짜별 다이제스트. `index.html`(루트)은 최신 날짜의 미러.
- **`test/index.html`** — `curate.yml`을 `test_mode=true`로 실행했을 때만 쓰는 폴더. 실 데이터(날짜 폴더·루트 미러)를 건드리지 않고 결과만 확인할 수 있습니다.
- **`pending-publish.json`** — 발행 예약 상태(`{date, test_mode, scheduled_at}`). 예약이 없으면 `{}`. 발행·정리 후 다시 비워집니다.
- **`rejected-articles.json`** — 검수 중 교체로 밀려난 기사(`{url, title, rejected_at}`) 기록. 다음 큐레이션이 이 목록을 참고해 버려진 기사를 다시 뽑지 않습니다.
- **`manifest.json` / `icons/`** — `trigger.html`을 모바일 홈 화면에 PWA(webclip)로 설치하기 위한 자산.

### 운영 대시보드 (`trigger.html`)

모바일에서 여는 단일 페이지 컨트롤 패널. **생성 / AI / 편집 / 더보기** 4개 탭으로 구성됩니다.

- **생성 탭** — 새 큐레이션 생성. `curate.yml`을 `workflow_dispatch`로 호출 (수동 실행은 항상 `force_run=true`로 공휴일·중복 가드 우회).
- **AI 탭** — 자연어로 HTML을 직접 편집. `command.yml`을 `workflow_dispatch`로 호출.
- **편집 탭** — 기사 교체 / 순서 조정 / 썸네일 교체 / 링크 수정.
  - 기사 교체는 `curate.yml`을 재호출(교체 URL만 다시 큐레이션).
  - 순서 조정·썸네일 교체·링크 수정은 워크플로우를 거치지 않고, 브라우저가 GitHub contents API로 해당 날짜 폴더 + 루트 `index.html`을 직접 읽어 고쳐서 한 커밋으로 push합니다.
- **더보기 탭** — 발행 예약/취소, 즉시 게시, 테스트 게시(개인 아지트), 다음 영업일로 미루기, 이번 달 발행 현황 그리드, 최근 액션 로그, GitHub 토큰 등 초기 설정.
  - 발행 예약/취소는 `pending-publish.json`을 GitHub contents API로 직접 커밋. 즉시 게시/테스트 게시/미루기는 각각 `agit-post.yml`/`repurpose.yml`을 `workflow_dispatch`로 호출.
  - 발행 관련 액션(예약·취소·즉시 게시·미루기)에는 별도 숫자 비밀번호 확인 단계가 걸려 있습니다.
- 이미 발행된 다이제스트를 덮어쓰지 않도록, 덮어쓰기 성격의 액션에는 발행 상태 기반 가드(`checkActiveCurationDate`)가 걸려 있습니다.

## 큐레이션 로직

- **소스**: 국내외 프로덕트·디자인·테크 블로그 및 뉴스룸의 화이트리스트를 스캔해 후보를 모읍니다. (`CURATE_MODE=web_search`로 전환하면 Claude의 웹 검색으로 인터넷 전체에서 큐레이션할 수도 있습니다.)
- **선정·요약**: Claude API가 후보 중 8개를 선정하고, 각 기사에 한 줄 요약 + 3줄 요약을 생성합니다.
- **인트로**: 선정된 8개를 종합해 "왜 지금 이 주제들이 중요한가(so-what)" 관점의 다이제스트 인트로를 생성합니다. 최근 인트로들과 톤이 겹치지 않도록 회피 로직이 있습니다.
- **본문 스크랩 폴백**: 일반 요청을 로그인 페이지로 리다이렉트하는 사이트(예: 브런치)를 대비해, 인증 리다이렉트를 감지하면 검색 크롤러 User-Agent로 재시도하고, 그래도 안 되면 렌더링 브라우저 → 캐시 순으로 폴백합니다.
- **중복 방지**: 같은 큐레이션 내 중복 및 과거 발행 기사와의 중복을 제거합니다.
- **버려진 기사 회피**: 검수 중 교체로 밀려난 기사는 `rejected-articles.json`에 쌓이고, 이후 큐레이션에서 후보에서 제외됩니다.

## 발행 흐름

1. 검수를 마치면 `trigger.html`에서 발행을 예약 → GitHub contents API로 `pending-publish.json`에 대상 날짜·시각을 직접 커밋합니다 (workflow_dispatch가 아닌 파일 커밋 방식).
2. 외부 cron이 아침(09:30 KST)에 게시 워크플로우를 호출 → `pending-publish.json`을 확인해 **예약 날짜가 오늘과 일치할 때만** 발행합니다. `trigger.html`의 "즉시 게시"는 `skip_wait=true`로 예약을 무시하고 바로 발행합니다.
3. 게시 직전 **데이터 유효성 검증**(기사 제목·인트로 추출 가능 여부)을 먼저 돌려, 문제가 있으면 게시하지 않고 즉시 알림을 보냅니다. 발행 시각 전에 여유를 두고 고칠 수 있습니다.
4. 발행 후 `pending-publish.json`을 비웁니다. (단, 미래 날짜 예약이 남아 있으면 보존)
5. **예약 어긋남 처리**: 예약 날짜가 오늘과 다르면 발행을 건너뛰고 알림을 보냅니다. 과거(stale) 예약이면 자동으로 정리하고, 미래 예약이면 해당 날짜 아침에 다시 시도합니다.

발행이 놀금·공휴일과 겹쳐 건너뛴 다이제스트는 `repurpose.yml`(다음 영업일로 미루기)로 다음 영업일에 재배치하고, 그 날짜로 발행 예약까지 자동으로 걸어 둡니다.

## 알림

두 가지 경로로 KakaoWork 알림이 나갑니다.

- **콘텐츠 변경 알림 (`notify.yml`)** — 큐레이션·교체·순서·썸네일·링크·AI 명령 커밋은 모두 Pages 재배포를 유발하고, 그 배포가 끝난 시점(=사이트가 실제로 새 내용을 서빙하는 시점)에 결과 알림이 발사됩니다. 커밋 메시지 첫 글자(이모지)로 어떤 액션이었는지 분류해 라벨과 다이제스트 링크를 함께 보냅니다.
- **발행 완료 알림 (`agit-post.yml` 자체 발사)** — Agit 게시가 끝나면 Pages 배포를 기다리지 않고 즉시, 스레드 링크 CTA 버튼이 달린 알림을 직접 보냅니다. `notify.yml`은 중복 방지를 위해 이 커밋을 라벨링 대상에서 제외합니다. `repurpose.yml`(다음 영업일로 미루기)도 같은 방식으로 자체 성공/실패 알림을 보냅니다.

콘텐츠 워크플로우가 실패해 배포까지 못 가는 경우(`notify.yml`이 못 잡는 실패)에는 워크플로우 실패 자체를 Actions 로그 링크와 함께 별도로 알립니다.

## 기술 스택

- **자동화**: GitHub Actions (`workflow_dispatch` 중심) + 외부 cron(cron-job.org) + GitHub contents API(브라우저에서 직접 파일 커밋)
- **호스팅**: GitHub Pages
- **AI**: Claude API (기사 선정·요약·인트로·자연어 명령)
- **스크래핑**: requests / Playwright / 검색 크롤러 UA 폴백
- **알림**: KakaoWork Incoming Webhook (Block Kit)
- **런타임**: Python 3.11
