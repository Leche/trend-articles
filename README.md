# 트렌드림 (Trend Dream)

매일 아침, 프로덕트·기술 아티클을 자동으로 큐레이션해 다이제스트로 만들어 발행하는 개인 운영 파이프라인입니다. GitHub Actions·GitHub Pages·Claude(팀플랜 구독, Claude Code CLI)·외부 cron·KakaoWork 봇을 조합해, **"전날 밤 초안 자동 생성 → 모바일에서 검수 → 다음날 아침 자동 발행"** 흐름을 무인에 가깝게 운영합니다.

- **결과물**: https://leche.github.io/trend-articles/
- **운영 대시보드**: `trigger.html` (모바일에서 검수·수정·발행을 조작하는 컨트롤 패널)

---

## 운영 컨셉

하루 사이클은 세 단계로 나뉘고, **전날 밤 22시에 다음날 다이제스트를 미리 만들어 두는 구조**입니다.

1. **생성 (자동, 무인, 전날 22:00 KST)** — 외부 cron이 `for_tomorrow=true`로 큐레이션 워크플로우를 깨워, **내일 KST** 날짜 폴더로 기사 8개를 선정·요약해 다이제스트 HTML을 만들고 커밋합니다.
2. **검수 (선택, 모바일)** — 큐레이션이 끝나면 다음날 10:00 발행이 **자동으로 예약**됩니다(2026-10-11부터, 놀금 제외). 손댈 게 없으면 그대로 두고, 고치고 싶으면 `trigger.html`에서 예비 기사로 바꾸기·순서 조정·썸네일 교체·링크 수정을, 내보내기 싫으면 예약 취소나 미루기를 합니다.
3. **아침 브리핑 (자동, 08:50 KST)** — 오늘 예약이 있으면 KakaoWork로 아지트 제목과 기사 8개를 보냅니다. 출근길에 훑고, 손댈 게 있으면 트리거에서 1~2분짜리 편집(예비 기사 교체·순서·취소·미루기)만 합니다.
4. **발행 (자동, 예약, 10:00 KST)** — 외부 cron이 매일 아침 게시 워크플로우를 호출하고, `pending-publish.json`에 오늘 날짜 예약이 있으면 그룹 채널에 자동 게시합니다. 각 단계 결과는 KakaoWork로 알립니다.

**발행 시각은 2026-10-12부터 10:00**입니다(그 전 09:30). 리체가 9시 전후 지하철에서 검수하고 9:20쯤 회사에 도착하는데, 09:30 발행이면 URL 교체(3~8분)가 발행 전에 못 끝나는 날이 있었습니다. 10:00이면 출근길 창이 50분으로 늘어 어떤 편집이든 들어갑니다.

**왜 22시 생성 + 아침 발행으로 분리했는가**: 처음엔 22시에 큐레이션을 만들고 그 안에서 익일 10:00까지 대기(sleep)했다가 발행하는 단일 워크플로우로 설계했지만, GitHub Actions job은 최대 6시간 제한이 있어 11시간 넘는 sleep이 불가능했습니다. 그래서 생성(`curate.yml`)과 발행(`agit-post.yml`)을 완전히 분리된 두 워크플로우로 쪼개고, 그 사이 신호는 `pending-publish.json` 플래그 파일로 전달하는 구조로 바꿨습니다.

큐레이션 결과물은 **"발행 전 초안"** 이라는 점이 설계의 핵심입니다. 자동 생성이 실패하거나 품질이 아쉬우면 밤~아침 사이 손으로 고치면 되고, 자동화의 진짜 목표는 "발행 전 검수할 초안이 미리 준비되어 있는 것"입니다.

### 모델 호출 경로 (2026-10-13부터 팀플랜)

모든 모델 호출(`curate.py`·`command.py`)은 공용 모듈 `scripts/llm.py`를 거치고, `LLM_BACKEND` 레포 변수로 경로를 고릅니다. `cli`(현재 기본)면 러너에 Claude Code를 설치하고 `claude -p --json-schema --model --effort --tools ""`로 호출하며, 인증은 `claude setup-token`으로 만든 1년짜리 구독 토큰(`CLAUDE_CODE_OAUTH_TOKEN` 시크릿)입니다. 공식 문서대로 OAuth 토큰이면 API 과금 대신 구독(리체 팀플랜 자리)을 씁니다. `api`면 예전처럼 `ANTHROPIC_API_KEY`로 과금됩니다. 워크플로 입력 `llm_backend`로 한 번만 바꿔 돌릴 수도 있습니다. 토큰은 1년 뒤(2027-10) 만료되니 그 전에 다시 발급해 시크릿을 갈아야 합니다. 만료·차단 등으로 실패할 때 API 경로로 되돌리려면, 콘솔(개인 조직)에서 키를 새로 만들어 레포 시크릿 `ANTHROPIC_API_KEY`에 넣고 `gh variable set LLM_BACKEND --body api`를 실행합니다. **2026-10-13부터 이 시크릿은 레포에 없습니다** — 과금 경로를 원천 차단하려고 지웠습니다. 코드 쪽 api 경로는 롤백용으로 남겨 두었습니다.

**과금 가드.** cli 모드에서 `ANTHROPIC_API_KEY`가 환경에 있으면 키가 OAuth 토큰보다 우선돼 API로 과금됩니다. 그래서 워크플로는 키를 `API_KEY_FOR_API_MODE`라는 다른 이름으로 받아 api 모드일 때만 bash에서 export하고, `llm.py`는 cli 자식 프로세스 환경에서 키를 한 번 더 지운 뒤 `🔒 과금 가드` 로그를 남깁니다. 2026-10-13 cli 테스트 두 번(그중 하나는 웹 발굴 도중 취소)에서 GitHub 표현식 `cond && '' || secret`이 빈 문자열을 거짓으로 보고 시크릿으로 떨어져 키가 들어간 사고가 있었습니다. 취소한 실행도 취소 전까지의 호출(웹 검색 17회, Haiku 5.5 검색 처리 포함)은 전부 과금됩니다. **워크플로 표현식 삼항에 빈 문자열을 쓰지 마세요.**

**사용량 감각** (2026-10-13 러너 실측, API로 환산했다면): 웹 리서치 발굴 $0.44 + 선정 $0.32 + 요약 $0.13 + 인트로·so-what·예비 $0.23 ≈ 회당 $1.1, 실행 8분. 팀플랜 자리 한도에서 빠지며 실제 결제는 없습니다. Anthropic 콘솔(개인 조직 "리체's Individual Org")의 결제 페이지 '지출 한도' 사용액이 늘지 않으면 정상입니다. 자동 충전은 꺼 두었고 잔액은 롤백용으로 남겨 둡니다.

### 새벽 재시도 (2026-10-19)

밤 22시 큐레이션이 실패하면(팀플랜 한도 등) 평일 05:30 외부 cron이 `curate.yml`을 입력 없이 한 번 더 호출합니다. guard가 오늘 날짜 폴더가 이미 있으면 건너뛰므로 밤 실행이 성공한 날은 아무 일도 하지 않고, 실패한 날만 오늘자를 만들어 같은 커밋에 오늘 10:00 발행을 자동 예약합니다. 재시도까지 실패하면 예약이 없어 08:50 브리핑이 오지 않습니다 — 그게 신호입니다.

### 휴가 스위치

쉬는 동안 발행도 브리핑도 멈추려면 cron-job.org에서 **22:00 큐레이션 잡과 05:30 재시도 잡을 끄면** 됩니다. 큐레이션이 안 돌면 예약이 안 생기고, 10:00 발행과 08:50 브리핑은 예약이 없으면 조용히 건너뜁니다. 복귀하면 다시 켭니다.

### 왜 외부 cron인가

GitHub Actions의 `schedule:` 트리거는 인덱싱이 비결정적이라 정시 실행 누락이 잦습니다. 그래서 native schedule을 제거하고, **외부 cron(cron-job.org)이 정해진 시각에 `workflow_dispatch`를 호출**하는 구조로 전환했습니다. 발화 신뢰도가 올라가고, 실행 주체(자동 cron / 모바일 수동)를 구분해 다루기도 쉬워졌습니다.

## 구성 요소

### 워크플로우 (`.github/workflows/`)

| 파일 | 이름 | 역할 |
|------|------|------|
| `curate.yml` | 트렌드림 기사 큐레이션 | 기사 선정 → 요약 → 썸네일 → HTML 생성. 전날 22시 자동 실행(`for_tomorrow=true`) 및 모바일 수동 실행 |
| `agit-post.yml` | Agit 게시 | 예약 시각에 다이제스트를 그룹 채널에 게시(v4: 헤드라인 제목 + 앞 5개 본문형 + 나머지 제목 링크). 게시 전 데이터 유효성 검증 |
| `notify.yml` | Notify Digest | Pages 배포 성공 시 결과 알림, 콘텐츠 워크플로우 실패 시 실패 알림 |
| `command.yml` | 트렌드림 AI 명령 실행 | 자연어 명령을 Claude가 해석해 HTML을 직접 수정 |
| `repurpose.yml` | 다이제스트 다음 영업일로 미루기 | 놀금·공휴일로 건너뛴 다이제스트를 다음 영업일로 재활용 |
| `morning-brief.yml` | 아침 발행 브리핑 | 평일 08:50 외부 cron이 호출. `pending-publish.json`에 오늘 예약이 있을 때만 아지트 제목·기사 8개·예비 기사 수를 KakaoWork로 보냄(출근길 마지막 확인용). 공휴일·놀금·휴가·취소·이미 게시한 날은 예약이 없어 조용함 |

### 스크립트 (`scripts/`)

- **`curate.py`** — 큐레이션 엔진. 웹 리서치 발굴 + 피드·사이트·서핏 스캔 → 기사 선정 → 본문 읽고 요약 → 썸네일 → 인트로·헤드라인·so-what → HTML·예비 기사 조립. 기사 교체(replace) 모드, 인트로 다시 쓰기 모드, 다음날 폴더로 생성하는 `for_tomorrow` 모드도 포함.
- **`command.py`** — 자연어 명령 해석기. "N번 기사 링크 교체", "제목 수정" 등을 Claude로 파싱해 HTML을 수정.
- **`llm.py`** — 모델 호출 공용 모듈. `LLM_BACKEND=cli`면 `claude -p`(팀플랜 토큰), `api`면 Anthropic API. 응답을 같은 모양으로 감싸 호출부는 경로를 모릅니다. 과금 가드도 여기 있습니다.
- **`inject_gnb.py`** — 생성된 HTML에 공통 내비게이션(GNB)·앵커 링크를 주입.

### 데이터 파일 (저장소 루트)

- **`YYYY-MM-DD/index.html`** — 날짜별 다이제스트. `index.html`(루트)은 최신 날짜의 미러.
- **`YYYY-MM-DD/thumb-N.ext`** — 기사별 썸네일 파일(WebP, 16:10 센터 크롭, 폭 ≤ 960px로 정규화 — 트리거 업로드도 같은 규격). 다이제스트 페이지의 `<img>`와 아지트 본문이 모두 이 파일을 참조하며, HTML에 base64를 넣지 않습니다. 루트 미러는 `YYYY-MM-DD/thumb-N.ext`처럼 날짜가 붙은 경로를 씁니다. 비디오 썸네일(mp4)만 HTML에 인라인으로 남습니다.
- **`test/index.html`** — `curate.yml`을 `test_mode=true`로 실행했을 때만 쓰는 폴더. 실 데이터(날짜 폴더·루트 미러)를 건드리지 않고 결과만 확인할 수 있습니다.
- **`pending-publish.json`** — 발행 예약 상태(`{date, test_mode, scheduled_at}`). 예약이 없으면 `{}`. 발행·정리 후 다시 비워집니다.
- **`rejected-articles.json`** — 검수 중 교체로 밀려난 기사(`{url, title, rejected_at}`) 기록. 전량은 재선정을 막고, 최근 40건은 선정 프롬프트에 "이런 결은 고르지 마세요" 반례로 들어갑니다.
- **`picked-articles.json`** — 검수 중 교체·예비 기사로 직접 넣은 기사(`{url, title, picked_at}`) 기록. 최근 30건이 선정 프롬프트에 "이런 결을 고르세요" 예시로 들어갑니다. 2026-10-11 git 히스토리의 교체 커밋에서 170건을 부트스트랩했습니다.
- **`YYYY-MM-DD/reserve.json` + `reserve-thumb-K.ext`** — 예비 기사(기본 3개). 본문 8개 다음 순위 기사를 요약·썸네일·헤드라인·so-what까지 미리 만들어 둔 것으로, 트리거가 워크플로 없이 바로 바꿔 끼웁니다. 다이제스트 HTML에는 넣지 않습니다(안 쓴 예비 기사가 '이미 실린 기사'로 잡혀 다음 큐레이션에서 막히지 않게).
- **`manifest.json` / `icons/`** — `trigger.html`을 모바일 홈 화면에 PWA(webclip)로 설치하기 위한 자산.

### 운영 대시보드 (`trigger.html`)

모바일에서 여는 단일 페이지 컨트롤 패널. **생성 / AI / 편집 / 더보기** 4개 탭으로 구성됩니다.

- **생성 탭** — 새 큐레이션 생성. `curate.yml`을 `workflow_dispatch`로 호출 (수동 실행은 항상 `force_run=true`로 공휴일·중복 가드 우회).
- **AI 탭** — 자연어로 HTML을 직접 편집. `command.yml`을 `workflow_dispatch`로 호출.
- **편집 탭** — 예비 기사로 바꾸기 / URL로 기사 교체 / 순서 조정 / 썸네일 교체 / 링크 수정.
  - 예비 기사로 바꾸기는 `reserve.json`을 읽어 카드 HTML·아지트 데이터·썸네일(blob 재사용)·취향 기록을 한 커밋으로 바꾸고, 인트로만 `refresh_intro`로 백그라운드에서 다시 씁니다. 기다림이 없습니다.
  - URL로 기사 교체는 `curate.yml`을 재호출(교체 URL만 다시 큐레이션, 3~8분).
  - 순서 조정·썸네일 교체·링크 수정은 워크플로우를 거치지 않고, 브라우저가 GitHub contents API로 해당 날짜 폴더 + 루트 `index.html`을 직접 읽어 고쳐서 한 커밋으로 push합니다.
- **더보기 탭** — 발행 예약/취소, 즉시 게시, 테스트 게시(개인 아지트), 다음 영업일로 미루기, 이번 달 발행 현황 그리드, 최근 액션 로그, GitHub 토큰 등 초기 설정.
  - 발행 예약/취소는 `pending-publish.json`을 GitHub contents API로 직접 커밋. 즉시 게시/테스트 게시/미루기는 각각 `agit-post.yml`/`repurpose.yml`을 `workflow_dispatch`로 호출.
  - 발행 관련 액션(예약·취소·즉시 게시·미루기)에는 별도 숫자 비밀번호 확인 단계가 걸려 있습니다.
- 이미 발행된 다이제스트를 덮어쓰지 않도록, 덮어쓰기 성격의 액션에는 발행 상태 기반 가드(`checkActiveCurationDate`)가 걸려 있습니다.

## 큐레이션 로직

- **소스**: 국내외 프로덕트·디자인·테크 미디어·뉴스룸의 **RSS/Atom 피드**(제목·발행일·요약 포함)를 1차로, 피드가 없는 사이트는 HTML 링크 스캔으로, 서핏은 Playwright로 후보를 모읍니다. 서핏은 **홈 피드를 3번 스크롤해 60장** + 카테고리 4개 첫 화면 18장씩을 봅니다(2026-10-12. 그 전엔 카테고리당 5장이라 리체가 손으로 뒤지던 홈 피드 깊이를 못 따라갔습니다). 툴 소개 카드는 제외하고, 긱뉴스 같은 한 출처가 서핏 자리를 다 먹지 않게 출처당 8개로 막습니다. 서핏 링크는 최종 URL로 풀어 실제 출처를 함께 보여줍니다.
- **웹 리서치 발굴 (1순위, 2026-10-13)**: 모델(Sonnet 5.5)이 WebSearch로 최근 2주 기사를 직접 찾습니다(검색 최대 15회, 후보 25개 안팎). 국내 언론·뉴스룸처럼 RSS에 없는 출처가 여기서 들어옵니다. 취향 목록(넣은·뺀 기사)과 이미 실린 기사를 같이 넣어 피하게 합니다. CLI 백엔드(팀플랜)에서만 켜집니다 — API 백엔드는 검색 과금이 있어 끕니다(2026-09에 회당 $7로 접었던 이유). 실패하면 보조 수집만으로 진행합니다.
- **디자인 슬롯 (2026-10-14)**: 본문 8개 중 2개는 디자인 기사나 좋은 글입니다 — 브랜드·서체·아이콘·UI 리디자인, 디자인 시스템, UX 케이스 스터디, 구체 사례 중심의 디자인·프로덕트 에세이. 개인의 AI 디자인 작업기·체크리스트·추상 전망은 제외. 선정이 기사마다 `design` 플래그를 달고, `ensure_design_slots()`가 선정 직후와 요약 후 두 번 본문 범위 안에 2개를 보장합니다(모자라면 뒤 순위의 디자인 글을 끌어올림). 웹 발굴도 디자인 후보를 6개 이상 찾게 합니다.
- **카카오 관련 소식 제외 (2026-10-14)**: 독자 대부분이 카카오 크루라 자사 소식(카카오·카카오톡·카카오뱅크·카카오페이·카나나 등)은 다루지 않습니다. 발굴·선정 프롬프트에 명시하고, 후보 단계(URL 도메인·제목·요약)와 본문 요약 후 단계에서 코드로 한 번 더 거릅니다(`is_kakao_related`). 브런치의 외부 작가 글은 자사 소식이 아니라 막지 않습니다.
- **보조 수집**: 아래 RSS·HTML·서핏 수집은 웹 발굴과 겹치지 않는 것만 뒤에 붙습니다. 선정 프롬프트에 "(web) 출처가 1순위, 피드·서핏은 빈 축을 메우는 보조"라고 적혀 있습니다.
- **선정**: Claude(Opus 5.5, 2026-10-13부터)가 후보(제목·날짜·요약)만 보고 본문 8 + 예비 3 + 여유분 4개를 **독자가 넣을 가능성 높은 순**으로 고릅니다. 후보 목록 밖 URL은 버립니다. 검수 때 직접 넣은 기사(최근 30)와 뺀 기사(최근 40)를 짝지어 취향 기준점으로 넣고, 반복해서 빠진 유형(투자 유치, 개인 AI 활용기·제작기, 작은 회사 리브랜딩, 추상 전망·체크리스트, 사용법 팁)은 피하며, 같은 뉴스는 공식 발표 원문을 우선합니다.
- **요약**: 최종 8개의 **본문을 읽고** 한국어 제목 + 한 줄 요약 + 3줄 요약을 한 번의 호출로 씁니다. (2026-09-09 이전엔 선정 호출이 URL·앵커 텍스트만 보고 요약까지 썼습니다.)
- **기사 순서 규칙 (2026-10-15)**: 최초 큐레이션은 코드가 순서를 정합니다. 앞 5개(아지트 본문형)는 뉴스(회사·서비스·기관이 실제로 한 일), 뒤 3개(아지트 링크형)는 읽을거리(에세이·케이스 스터디·디자인 글). 1번은 인트로 호출이 뉴스 중에서 고른 "그날 가장 큰 사건"이고, 같은 묶음 안에서는 선정 순서를 유지합니다. 9~10월 28일치에서 리체가 손본 최종 순서를 집계한 결과(읽을거리 31건 중 23건이 6~8번, 최종 1번 28일 중 22일이 뉴스)에서 뽑은 규칙입니다. 선정이 기사마다 `kind`(news/read)를 달고 `apply_order_rules()`가 정렬합니다. 교체·순서 조정 뒤에는 적용하지 않습니다.
- **헤드라인·인트로**: 선정된 8개를 종합해 인트로(150~200자, 첫 문장은 구체적 사건)와 **기사별 헤드라인**(25~40자 사건 단문), 훅이 가장 센 리드 기사를 한 호출로 생성합니다. 새 큐레이션은 리드 기사를 1번으로 올리고, 아지트 글 제목은 항상 1번 기사의 헤드라인을 씁니다 — 트리거에서 순서를 바꾸면 제목이 따라갑니다. 기사 교체 때는 순서를 존중합니다. 최근 인트로들과 톤이 겹치지 않도록 회피 로직이 있습니다.
- **본문 스크랩 폴백**: 일반 요청을 로그인 페이지로 리다이렉트하는 사이트(예: 브런치)를 대비해, 인증 리다이렉트를 감지하면 검색 크롤러 User-Agent로 재시도하고, 그래도 안 되면 렌더링 브라우저 → 캐시 순으로 폴백합니다.
- **중복 방지**: 같은 큐레이션 내 중복 및 과거 발행 기사와의 중복을 제거합니다.
- **버려진 기사 회피**: 검수 중 교체로 밀려난 기사는 `rejected-articles.json`에 쌓이고, 이후 큐레이션에서 후보에서 제외됩니다.

## 발행 흐름

1. 밤 큐레이션(`for_tomorrow=true`)이 결과물과 같은 커밋에 `pending-publish.json`(`auto: true`)을 써서 다음날 발행을 자동 예약합니다. 놀금은 예약하지 않고, 더 뒤 날짜 예약이 있으면 건드리지 않습니다. 수동 예약·취소는 `trigger.html`이 GitHub contents API로 같은 파일을 직접 커밋합니다.
2. 외부 cron이 아침(10:00 KST)에 게시 워크플로우를 호출 → `pending-publish.json`을 확인해 **예약 날짜가 오늘과 일치할 때만** 발행합니다. `trigger.html`의 "즉시 게시"는 `skip_wait=true`로 예약을 무시하고 바로 발행합니다.
3. 게시 직전 **데이터 유효성 검증**(기사 제목·인트로 추출 가능 여부)을 먼저 돌려, 문제가 있으면 게시하지 않고 즉시 알림을 보냅니다. 발행 시각 전에 여유를 두고 고칠 수 있습니다.
4. 발행 후 `pending-publish.json`을 비웁니다. (단, 미래 날짜 예약이 남아 있으면 보존)
5. **예약 어긋남 처리**: 예약 날짜가 오늘과 다르면 발행을 건너뛰고 알림을 보냅니다. 과거(stale) 예약이면 자동으로 정리하고, 미래 예약이면 해당 날짜 아침에 다시 시도합니다.

발행이 놀금·공휴일과 겹쳐 건너뛴 다이제스트는 `repurpose.yml`(다음 영업일로 미루기)로 다음 영업일에 재배치하고, 그 날짜로 발행 예약까지 자동으로 걸어 둡니다.

## 알림

두 가지 경로로 KakaoWork 알림이 나갑니다.

- **콘텐츠 변경 알림 (`notify.yml`)** — 큐레이션·교체·순서·썸네일·링크·AI 명령 커밋은 모두 Pages 재배포를 유발하고, 그 배포가 끝난 시점(=사이트가 실제로 새 내용을 서빙하는 시점)에 결과 알림이 발사됩니다. 커밋 메시지 첫 글자(이모지)로 어떤 액션이었는지 분류해 라벨과 다이제스트 링크를 함께 보냅니다.
- **발행 완료 알림 (`agit-post.yml` 자체 발사)** — Agit 게시가 끝나면 Pages 배포를 기다리지 않고 즉시, 스레드 링크 CTA 버튼이 달린 알림을 직접 보냅니다. `notify.yml`은 중복 방지를 위해 이 커밋을 라벨링 대상에서 제외합니다. `repurpose.yml`(다음 영업일로 미루기)도 같은 방식으로 자체 성공/실패 알림을 보냅니다.

콘텐츠 워크플로우가 실패해 배포까지 못 가는 경우(`notify.yml`이 못 잡는 실패)에는 워크플로우 실패 자체를 Actions 로그 링크와 함께 별도로 알립니다.

## 기술 스택

- **자동화**: GitHub Actions (`workflow_dispatch` 중심) + 외부 cron(cron-job.org) + GitHub contents API(브라우저에서 직접 파일 커밋)
- **호스팅**: GitHub Pages
- **AI**: Claude Code CLI(`claude -p`) + 팀플랜 구독 토큰 — 웹 리서치 발굴(Sonnet 5.5)·선정(Opus 5.5)·요약(Sonnet 5.5)·인트로·헤드라인·so-what(Opus 5.5)·자연어 명령(Sonnet 5.5). 롤백용으로 Anthropic API 경로 유지
- **스크래핑**: requests / Playwright / 검색 크롤러 UA 폴백
- **알림**: KakaoWork Incoming Webhook (Block Kit)
- **런타임**: Python 3.11
